ZEROKEY TURNS A BROWSER SESSION YOU ALREADY OWN INTO AN OPENAI-COMPATIBLE ENDPOINT. YOU PASTE A FETCH() COPIED FROM YOUR OWN DEVTOOLS; ZEROKEY REUSES THAT SESSION COOKIE AND NEVER LEAVES YOUR MACHINE.

ONE SERVER PROCESS IS PINNED TO ONE PROVIDER, ONE USER, AND ONE SESSION. SWITCHING SESSIONS OR OPENING A NEW IDE CHAT DOES NOT RE-TARGET THE PROXY — RESTART THE SERVER TO SWITCH.

THE DEEPSEEK TRANSPORT RUNS A REAL CHROMIUM PROFILE VIA PLAYWRIGHT (TEMP/PROFILES/DEEPSEEK/ <USER>/) BECAUSE THE DIRECT HTTP API IS AGGRESSIVELY FLAGGED. THE BROWSER IS WHAT MAKES THE SESSION SURVIVE.

PROVIDERS

  • DEEPSEEK — BROWSER TRANSPORT (CHROMIUM + POW), API OPT-IN
  • CLAUDE — COMPLETION SSE (CONNECT-RPC OPT-IN)
  • CHATGPT — SENTINEL REFRESH + 401 RE-DECODE RECOVERY
  • QWEN — COOKIE TOKEN OR BEARER, PERSONALIZATION
  • INCEPTION (MERCURY) — AUTHLESS BROWSER TRANSPORT

IDES_SUPPORTED

  • TERAX

THE TOOL SURFACE IS AUTO-DETECTED PER REQUEST FROM THE IDE SYSTEM PROMPT — NEVER FROM A HEADER OR CLIENT CLAIM.

FAQ

DOES ZEROKEY COST ANYTHING?

A: NO. ZEROKEY ITSELF IS FREE AND OPEN SOURCE; YOU STILL NEED YOUR OWN PROVIDER ACCOUNT.

DOES ZEROKEY SEE MY PASSWORD OR API KEY?

A: NO. NO API KEY IS INVOLVED — ONLY THE SESSION COOKIE YOU CHOOSE TO SHARE, AND IT STAYS ON YOUR MACHINE.

WHAT HAPPENS IF MY SESSION EXPIRES?

A: RE-PASTE A FRESH FETCH() IN THE SETUP WIZARD. SESSIONS OTHERWISE PERSIST ACROSS RESTARTS.

CAN I SWITCH PROVIDERS LATER?

A: YES. RESTART THE WIZARD AND PICK A DIFFERENT PROVIDER; NO IDE RECONFIGURATION NEEDED.

IS USING ZEROKEY AGAINST A PROVIDER TERMS OF SERVICE?

A: YOU USE YOUR OWN ACCOUNT THROUGH YOUR OWN BROWSER SESSION, BUT YOU ARE RESPONSIBLE FOR READING AND COMPLYING WITH EACH PROVIDER TERMS OF SERVICE. ZEROKEY CREATES NO ACCESS AND BYPASSES NO AUTHENTICATION.
